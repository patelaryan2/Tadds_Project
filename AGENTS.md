# Project Instructions

## General Rules
- Inspect the existing project structure and relevant code before making changes.
- Understand existing patterns and architecture before implementing anything.
- Make the smallest necessary changes to complete the requested task.
- Do not modify unrelated files.
- Follow the project's existing coding style and architecture.
- Reuse existing dependencies and utilities where appropriate.
- Do not introduce unnecessary dependencies.
- Keep code clean, readable, maintainable, and modular.

## Development Workflow
1. Understand the user's task.
2. Inspect relevant files.
3. Identify existing functionality that can be reused.
4. Plan the implementation.
5. Implement the required changes.
6. Run relevant tests or validation.
7. Review the changes for errors and unintended modifications.
8. Summarize what was changed.

## Security
- Never expose API keys, passwords, tokens, credentials, or other secrets.
- Do not commit secrets to Git.
- Do not modify environment or security configuration unless required by the task.

## Git
- Do not create commits automatically unless explicitly requested.
- Do not push changes automatically unless explicitly requested.
- Review changed files before suggesting a commit.
