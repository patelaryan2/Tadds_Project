SUMMARY OF CHANGES

1. What changes were done:
- Migrated data fetching and authentication from local/hardcoded data to a live Supabase database.
- Converted core data layer files and React contexts to TypeScript.
- Added form validations for the authentication page (email format, password length) and checkout page (empty cart check).
- Replaced currency symbol `$` with `Rs` globally across Product Details, Product Cards, and Checkout pages.

2. Why specific files were converted to .tsx/.ts (and not all):
- We only converted `AuthContext`, `CartContext`, `products`, and `supabase` files to TypeScript.
- Reason: TypeScript adds the most value in files that deal with data shapes, APIs, and shared state (e.g., ensuring a Product always has an `id`, `name`, and `price`). 
- We left simple UI components (like `Navbar.jsx` or `App.jsx`) as `.jsx` because converting them wouldn't prevent many bugs; it would just add unnecessary boilerplate to simple presentational code. This incremental, mixed-language approach saves time and keeps the codebase simple while still getting the safety of TypeScript exactly where it matters most.

3. How Supabase was integrated:
- Setup: We created a central Supabase client (`src/lib/supabase.ts`) using the project URL and anon key stored in `.env.local`.
- Auth Integration: Replaced `localStorage` logic in `AuthContext.tsx` with `supabase.auth.signUp`, `signInWithPassword`, and `signOut`. We also added an `onAuthStateChange` listener to automatically persist the user's session when they refresh the page.
- Database Integration: Replaced the hardcoded product array in `products.ts` with a `supabase.from('products').select('*')` query to fetch the live inventory from your Postgres table. 
- Cart Caching: `CartContext` was updated to asynchronously fetch and cache the Supabase products when the app loads, so cart total calculations can still happen instantly and synchronously.
- Rate Limits: We bypassed the Supabase free-tier email limit by disabling the "Confirm email" requirement directly in the dashboard, allowing for instant user signups during development without SMTP issues.

4. TSX & CSS Classes Summary:
- TSX Usecase: Provide strict typing for data and state to prevent bugs (e.g., AuthContext.tsx).
- Classes Added: Form layout classes added in Home.jsx, and secondary button classes in Checkout.jsx.
- Classes Removed: 'quantity-btn' and 'checkout-item-total' removed from Checkout.jsx.

5. JSX to TSX Migration Timeline:
- When: During the current uncommitted changes (part of the Supabase data migration) to enforce stricter data typing.

6. CRUD Operations Summary:
- Where: Logic in src/data/products.ts; UI in src/pages/Home.jsx & src/components/ProductCard.jsx.
- Functions Added: 'createProduct', 'updateProduct', 'deleteProduct' (Supabase logic); 'loadProducts', 'handleSubmit', 'handleEdit', 'handleDelete' (Form logic).
- Classes/UI Added: Form styling classes ('auth-container', 'form-group', 'btn-block', etc.) in Home.jsx; Edit/Delete inline buttons in ProductCard.jsx.
- What's New: A complete admin interface on the Home page to Create, Edit, and Delete products directly in the live database.

7. CRUD Function Definitions & Flow:
- ProductCard Props: 'onEdit' and 'onDelete' are props triggered in 'ProductCard.jsx'.
- Home.jsx (Event Handlers): The actual execution functions ('handleEdit', 'handleDelete', 'handleSubmit') are defined in 'src/pages/Home.jsx' and passed down to ProductCard.
- products.ts (Database Logic): 'Home.jsx' calls the core backend functions ('createProduct', 'updateProduct', 'deleteProduct') which are defined in 'src/data/products.ts' to talk to Supabase.

8. handleSubmit Breakdown (Home.jsx):
- e.preventDefault(): Stops the browser from refreshing the page on form submit.
- updateProduct/createProduct: Calls the backend to either update an existing item (if 'editingProduct' exists) or insert a new one.
- setShowForm(false) & setEditingProduct(null): Closes the UI form and clears the current edit session.
- setFormData(...): Resets all form fields to empty strings for the next use.
- loadProducts(): Re-fetches the list from Supabase so the new/updated product immediately appears on screen.
- alert(...): Shows an error pop-up if the database fails to save the product.
